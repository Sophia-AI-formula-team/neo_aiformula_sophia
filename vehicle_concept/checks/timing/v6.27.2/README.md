# Concept V6.27.2 部署包验收

实车入口是 `ros2 run concept live`。V6.27.2 默认使用加速后的路界计算，同一帧中，横向目标和要求速度的双精度值逐位相同的请求共享一次模拟。每个原始候选保留自己的编号、安全判定和分数。部署版只有精确去重这一种行为。V6.26 驾驶策略、B1.4 权重和 H12 排序权重沿用冻结版。

## 驾驶结果回归

从提交 `25630d0f3bbb9b7f4c191efb36e7a250ec85397a` 的 Git 归档，在独立 ROS 2 Foxy 工作区构建全部 12 个包。安装来源检查通过，默认规划请求上限为 15 Hz。Python 测试结果为 **32 passed in 2.08 seconds**。

按时间顺序回放内圈、移动桶、混合、平行双桶和连续障碍共 **1,079 帧**。驾驶程序实际模拟 **56,780 / 80,925** 项，减少 **29.8%**。逐帧核对所有候选表和轨迹、可行标记、最终选择及控制，五场均通过。回归进程特意带着上一轮 5 cm 和 0.05 m/s 的实验环境变量运行，并逐帧检查实际模式为 `exact`。[逐场结果](frozen-regression.json)

## 拍到图至收到新指令

在 Ryzen 9 7900X、RTX 4070 Ti 工作站的隔离 ROS 图中，按墙钟以 15 Hz 发布图像，GPU 每次重新运行 B1.4。每场 60 秒，300 张不同的 Unity 归档图各发三次，目标速度 1.0 m/s。内圈配归档轮速和陀螺，外圈使用固定轮速和零陀螺测试障碍记忆累积。新指令的时间戳必须对应本场图像和同次成功决策。一张图没有对应新指令计入“缺新指令图”。平均 Hz 取 60 秒接收窗，指令总数含末尾在途响应。

|---|---:|---:|---:|---:|---:|---:|---:|
| 内圈 | 900 / 900 | 804 | 96 | 13.37 | 10 | 141.7 | 132.6 / 181.6 / 235.3 |
