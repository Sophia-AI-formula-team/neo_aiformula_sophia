# inner05 topo 歧义：精确输入复现与数值未收敛证据

2026-11-16。本报告在任何 semantic 源修改之前完成。源码、官方OSM、融合阈值、车辆输入均未修改；仅审计进程包装返回参数，并对两个真实候选作无约束续算。Unity保持Edit期间完成，单个计算子进程3.59s退出，其中融合与续算2.67s。没有并行模型/GPU或第二个matcher执行者。

## 精确恢复了原运行输入

脚本 `inspect_recorded_fusion.py` 从 `inner_joint_05/worker/semantic_joint_ticks.jsonl` 找到第一条 `odom_reference_ready=true` 的tick，使用该帧 `map_data.learned_samples`，追加同帧 odom 的 `(x,y,yaw,excluded=False)`。这对应原 `MapAssist._try_complete_lap` 提交 `self.samples + [current]` 的实现，未用第二圈轨迹替代首圈。

原 `build_fused_route` 使用原YAML、原OSM、同样两个内部comparison points和原15轮上限。只在 `_to_alignment` 外包装保存 best/alternative 实参并原样调用返回；另记录候选来自 `_refine_candidate` 还是同transform受约束probe。重放与现场7项诊断——best/alternative RMSE、score gap、两个phase、最大节点差、闭合gap——**逐项绝对误差全部为0**。因此本次候选是现场同一数值结果，不只是形状相似的另一次输入。

完整输入、source/OSM SHA、参数、候选坐标、迭代轨迹都在 `inner05_fusion_candidates.json`，不进入控制。

## 原选中候选确有几何差，但来自两个尚未充分优化的seed

两者方向都为1，**都来自 refined_seed**，不是同transform主动排除1m区间生成的probe。原score分别0.178227764、0.244503206，差0.066275442；原RMSE为0.159297406m、0.222721802m。

| 点ID | 类型 | 原候选位置差 |
| --- | --- | ---: |
| 10000000000 | 外圈投影 | 0.240219m |
| 10000000001 | 外圈投影 | 1.004679m |
| 10000000002 | 外圈投影 | **1.484602m** |
| 10000000003 | 外圈投影 | 0.958203m |
| 10000000004 | 外圈投影 | 0.141717m |

故原来的>1m不是Python对象重复、phase环绕或内部节点ID误解造成；最大项是外节点10000000002。按当时的两个数值候选，原歧义判据执行正确。

但原 `_refine_candidate` 硬上限15轮并不检查是否已经收敛后才参与候选比较。把这两个实际输出各自作为seed，其他算法/参数不变，仅追加原迭代：

| 追加预算 | best score | alternative score | 两者最大几何差 | 最后transform change（best / alt） |
| ---: | ---: | ---: | ---: | --- |
| 0（现场） | 0.178227764 | 0.244503206 | 1.484602m | 原接口未记录 |
| 15 | 0.017005572 | 0.050758088 | 0.281810m | 0.00194777 / 0.00554244 |
| 60 | 0.001215110 | 0.001303232 | **0.002623m** | 0.00001692 / 0.00005042 |

追加60后RMSE为0.001115814m / 0.001187744m。两者仍略未达到原`change<1e-5`停止阈值，但几何已差约2.6mm，而不是1.48m。

**可支持的结论：本场被选中的这一对歧义，存在15轮提前结束导致同一数值解尚未汇合的强证据。** 不能继续笼统宣称“官方图与实际圈形必定不可观测”。这也不等于已证明整个69候选集合不存在另一真实近成本解。
