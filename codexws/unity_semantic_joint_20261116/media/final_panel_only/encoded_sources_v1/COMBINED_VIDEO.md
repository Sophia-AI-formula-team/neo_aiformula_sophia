# Two sealed cases, one PyAV encoding

Scope: add a two-case manifest and a sequential renderer; preserve the existing single-plan path. No source recording, semantic code, Unity setting, or failed baseline video is changed. No dependency installation or encoding belongs to this preparation step.

1. Prepare the final inner and outer recordings separately with `prepare --seconds 30 --backend pyav`. Each retains its whole source timeline, protected events, actual result and source hashes.
2. `combine --plans INNER_PLAN OUTER_PLAN --plan COMBINED_PLAN` seals exactly those two plan files in that order. It records contiguous integer frame ranges, global output PTS, per-case duration/name/source/result and the common pinned encoder. Different frame sizes/rates, renderer versions, encoders or duplicate source recordings are rejected. The actual combined duration is the sum of the two frame counts divided by 15; the tool reports any event-preservation extension instead of changing the subplans.
3. The existing `run_joint_bounded.py --plan COMBINED_PLAN ...` owns one renderer process. One PyAV output stream receives case 1 frames followed directly by case 2 frames, with monotonically increasing global PTS. It does not encode intermediate videos or re-encode them. A visible `[1/2]` / `[2/2]` case label identifies the cut; there is no implied continuous vehicle motion between independent runs. Only one case's large recording is loaded at a time.
4. Every output row records case identity, source plan hash, local frame/time, source wall time and start/end boundary flags. `case_boundaries.json` seals the exact output ranges. Each case retains its own final acceptance result; there is no invented combined success verdict.
5. Decode the complete single output once. Check all frame PTS, dimensions, format and count; read back the frame journal and verify every case/index/boundary against the combined plan. Export decoded start/middle/end frames for each case, including both sides of the cut. Recheck all source, child-plan, encoder and surface hashes after decoding. The existing 300-second Job deadline, one encoder/decoder thread, cleanup verification and no-retry rule continue to apply.

Completed static checks: Python and bootstrap syntax, CLI help, contiguous case frame ranges, exact frame selection on both sides of the cut, reset to each case's own source clock, forced inclusion of each case's final source endpoint, and preservation of the single-plan `source_time` behavior. The small in-memory mapping fixture loaded no real recordings, rendered no images and encoded no frames. Actual combined codec/visual checks require both completed final recordings and a root-owned CPU window; they are not claimed by these preparation checks.

The control diagnostics also expose the new recorded identity-adapter boundary: original overlay/raw model state, filtered model state, final control state and rejection reason remain distinct. This display change introduces no detector or controller behavior.
