# AI Formula 学习驾驶原型

[Unity 连续双桶试验与相机回放](unity_cones/README.md)记录了安装版车辆物理上的局部选边实验。下文是早期二维策略的独立结果。

打开 [双车回放](demo/replay.html) 可切换布局、拖动模拟时钟，查看两轮的指令和模型算出的车身速度。[窄门动图](demo/corner.gif) 把两辆车分别到达同一入口的瞬间对齐。图中的原始外环来自 Demo_LaneLineTrainer 的跑道资产，错位窄门是用于试验的附加布置。

## 哪些是学出来的

1. **车辆响应**。[dynamics.py](dynamics.py) 用 10 月 27 日四段实车 bag 的总线 0x210、VectorNav 水平速度和 IMU 偏航角速度拟合八个系数，并在五个候选延迟中选择一个。模型描述平均轮速带来的车速变化、部分收油与归零的响应速度、左右转弯增益和直行偏转。模型形式由人选择，数字由数据决定。使用 CAN 帧的时间加权均值，保留零帧。在手操训练记录中，发零指令期间有时车辆仍显著运动，仅使用其持续有正向指令的窗口，归零响应来自受控的阶跃记录。训练和预测均限定为向前行驶。
2. **开车策略**。[driving.py](driving.py) 的 25 个权重决定纵向轮速和左右轮速差。输入是车身坐标里 0、2、4、6、8 米处的左右边界、车速和偏航角速度。边界编码成中点与半开口，仍可还原两侧信息。策略在每次运行中都不接收全图、世界坐标、圈数、赛道进度、计时或弯号。每 0.1 秒输出一次动作。没有人工过弯示范标签，也没有外内外、刹车点或切弯点的位置表。
3. **练习方法**。每个布局从零均值的权重分布独立出发。交叉熵法每批采样 80 组权重，按行驶结果保留表现好的样本，再由这些样本更新下一批的均值与方差。每个布局练 26 批。合格策略优先于失败策略，再根据用时排序。尚未完成时，按出界或终止前前进的距离排序。紧门布局每组候选还要通过两种轻微变化的车况，评分综合最差和平均情形。首批达标指第一次出现满足该布局所有要求的候选时选出的策略。它和最终策略都在同一起点、同一标准车况下重新计时。
4. **临时车况估计**。可选的 OnlineResponse 根据上一拍实际车速、偏航和过去指令的预测误差，逐步更新车速增益和直行偏转估计，再修正下一拍的左右轮指令。估计器每次发车都归零。它看不到测试程序给车辆施加的扰动值。

人工指定的部分包括局部观察距离、模型和策略的数学形式、轮速上限、用于判定越界的 1.00 × 0.72 米代理轮位、0.12 米试验余量、完圈计时及训练预算。余量按四个代理点在其各自所在纵向位置的边界计算。本原型选择让四个点都留在边界内，严于本赛季四轮全出才判出界的规则。模拟器用完整几何生成局部观察和判定成绩，驾驶函数只收到那一步的局部数值。

## 结果与使用边界

| 布局 | 首批达标策略 | 训练后 | 保留训练后的转向，最佳固定纵向指令 |
| --- | ---: | ---: | ---: |
| 原始双车道外环 | 81.29 s | 76.60 s | 76.59 s |
| 外环加两组 9 m 错位门 | 130.23 s | 83.88 s | 83.84 s |
| 第二组门距缩至 7 m | 180.78 s | 98.61 s | 110.95 s |

对照扫描 80–300 RPM，间隔 2 RPM，所有方案使用相同的车轮限幅和边界。对照的转向仍会随观测变化，但没有在每个固定 RPM 上重新训练转向。差异说明这组已学转向在紧门布局上受益于可变纵向指令。原始外环上，训练后的策略几乎始终保持高轮速。

还把紧门策略的同一套权重直接用于三种布局，分别在 89.01、98.24、98.61 秒完成。上表则是各布局分别练习后的成绩。三种布局共用同一外环，尚未验证跨真实赛道泛化。

实车记录的独立检验只评估短时动力学。给定窗口开头的观测和随后实际发出的指令，预测 1 秒后的车速，在留出的 turn2、mixed1、lya2 上平均绝对误差分别是 0.11、0.27、0.71 m/s。持有当前车速不变的基准分别是 0.41、0.42、0.17 m/s。lya2 有零和非零指令交替且车辆持续行进的片段，简化模型在这段记录上误差明显。名称、样本数、偏航误差和源 bag 的 SHA256 均在 [模型文件](demo/dynamics.json)。

紧门策略在另设的四种模拟车况（速度增益 ×0.85 或 ×1.10，外加左右两方向的偏转）中，固定模型完成 0/4 圈，在线修正完成 2/4 圈。每个条件都在 [完整结果](demo/results.json) 中保留。扰动与估计器采用相近的数学形式，传感器理想，无轮胎滑移、颠簸或视觉误差。该检验不能辨认真实电池状态，也不能证明实车圈速、抓地极限或相对人的成绩。

## 运行与继续调整

Neo 基线为 `2ee51daccf2c8afd1448ea7eae82160cc44f6d75`。这里位于 `codexws/COLCON_IGNORE` 下，可直接在电脑上运行，程序没有 ROS/CAN 发送接口。运行环境使用 Python 3.11 以上、NumPy、SciPy 和 Pillow。

```powershell
# 在本目录运行。随附的车辆参数和策略足以重新闭环驾驶，并生成回放。
python experiment.py

# 改练习预算，用相同的 bag 拟合模型和模拟场地重新从零搜索策略
python experiment.py --train --generations 32 --population 96 --output my_run
python experiment.py --output my_run
```

单独使用 [驾驶权重](demo/driver.json) 只需局部边界和两项运动观测。该文件不包含赛道几何。下例给出车身坐标系下五处边界的横向位置，单位米，左为正，输出为右轮和左轮的目标 RPM。此入口只计算并打印数值。

```powershell
python inference.py --left 3.4 3.4 3.4 3.4 3.4 --right -3.4 -3.4 -3.4 -3.4 -3.4 --speed 2.0 --yaw 0
```
