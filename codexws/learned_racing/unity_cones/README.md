# Unity 连续双桶试验

[同步俯视回放](results/unity-cones.gif)使用 Unity 正交相机在实际物理步之后渲染的画面。上、下两趟共用同一仿真时钟。向画面右方行驶时，画面上方是车的左侧。

在已打开的 Unity 2022.3.22f1 中，从已保存的 `MotorControllerValidation.unity` 为每趟试验创建独立的预览物理场景。沿用安装版 `Archived1030` 转换器、`JanuaryLapIdentified` 执行器、前轮接触与耦合后轮铰链。车辆先在原出生位置静置 2 秒，随后每 0.01 秒调用原车的 `StepDrive` 和该场景的 `PhysicsScene.Simulate`。从刚体读出位姿用于反馈和评价。全程使用编辑器内的 PhysX，主场景处于 Edit Mode。

## 车辆看到什么

第一只桶始终在起点正前方 5.50 m。第二只在前方 8.00 m，分别向左、右偏 1.05 m。沿用场景原有路面和 `TrafficCone_75cm` 预制体。起步观测只返回被测桶的车身坐标，需要通过距离 10 m、左右各 40° 和视线射线检查。路边来自本地 12 m 内沥青与绿带、岛区的几何交界，两侧还受 2.6 m 试验半宽约束。这里给了理想的桶、路边和自身运动观测。相机只负责拍摄回放。没有接 A3 或加载赛道路线给驾驶策略。

## 哪些来自练习

- **练习**。无实验桶时在同一段路上尝试 33 组动作。每组由一个横向目标和行驶过程中目标的变化量定义，速度指令统一为 1.65 m/s。低层比例反馈根据车身位置、航向角和横摆角速度产生连续速度指令，经原车转换器输出左右轮 CAN。低层形式、三种变化量和动作范围由试验者指定。
- **预测**。27 趟在试验中心位置界限内到达 11 m，6 趟离开试验范围。保留全部记录，仅在连续成功的动作范围内插值，得到不同动作在每个前进距离上的横移、航向和耗时。8 趟未参与拟合的动作检验中，横移平均绝对误差为 0.0068 m，最大点误差为 0.0373 m。这些误差只描述同一仿真和起点。
- **选择**。根据空场练习预测 311 种动作的后果。保留预测避桶余量至少 0.22 m、路边余量至少 0.10 m 的方案，按预计耗时、平均横向偏移和目标变化量选取代价最小的一种。左右均由同一计算评价。初始决策只做一次，之后低层持续反馈。两只桶用相同低层和相同代价。消融版本只在起步决策中遮住第二只桶，Unity 场景仍有两只实体桶。

上述经验来自 Unity 试车和插值。目标、约束和排序准则是人工给出的。前一版二维驾驶策略的 25 个权重、实车图像识别、独立刹车动作、在线车况适应和中途重新选边属于另外的实验。

python -B experiment.py --sim "$sim" --output .work/reproduction --record-repeat --frames .work/reproduction/frames
