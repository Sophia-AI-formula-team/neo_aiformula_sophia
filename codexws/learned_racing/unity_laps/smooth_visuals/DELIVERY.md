# 长训练与可见中缝的真实驾驶录像

本轮的原始追车摄像、前视 A4 推理和左右轮命令均来自本机的 Unity 闭环。车辆控制使用 A4 道路和障碍观测。影片中场地俯视、实体走向、路界和最小净距通过裁判记录离线重建。实速来自物理日志，轮速差显示的是车辆发出的两侧 CAN 目标之差。

## 录像与复核

本机交付目录为本实验工作树的 `.work/offline-driving-review`。解压同名 ZIP 后直接打开 `index.html`，可看训练、控制对照、完整圈和中缝三臂的 17 段录像及两个合辑。逐片 SHA 和得分源文件身份保存在 [film_manifest.json](film_manifest.json)。包内 `evidence` 有逐段原始日志和相机证据的 SHA、解码像素误差、实测场景与判据。

主阶段无损合辑 227.10 秒，13 章共 4,542 帧。中缝合辑 35.40 秒，三章 708 帧，另附 G05 速度对照。两份合辑分别验证源录像与拼接录像在全部帧上的 120×68 灰度指纹一致。真实 JPEG 核验在每支短片覆盖首、中、末与动作/穿门时刻，逐文件 SHA-256 覆盖全包。Chrome 通过本地 file URL 切换和播放 G05、L02 成功。

## 数据与选例

- `smooth_revision` 中的 `runs`、`.work/frames`、`.work/camera` 提供 560 次强制训练、各检查点同场开发以及 24 组局部和 8 组整圈盲测。原始训练动作和开发复拍分别逐行校验车身物理状态、净距与最终左右轮指令。训练 054 动作 3 的上层浮点偏航指令最大差 0.00001097 rad/s，最终轮令一致。
- 三个原始检查点为 ck32、ck64、ck80。最终冻结 ck64，开发门槛未满足。参考与冻结策略的独立结果同为局部 23/24、整圈 6/8。B21 对照显示少转、更快，B05 显示转向增加。B10 中双方都碰桶。L02 是登记顺序中首个完成的整圈，L05 则是双方完成且用时相对降幅最大的整圈，86.92 → 79.19 秒。L01 两臂都失败，冻结策略更早出界。
- `gap_revision` 和 `gap_holdout/results.json` 给出另 8 个布局的三臂试次。G04/G07 展示实际可用开口，G08 保留寻缝碰桶。G05 三臂都从两排中间安全通过，相同障碍区用时为 11.18、5.40、7.49 秒。三阶段指令、实测进出门速度与车身完整通过情况分开展示。

## 复现入口

1. `smooth_delivery.py plan` 从独立评分确定原阶段场景。用 `training-choice` 添加摄像复现的训练布局 054、066，`development` 添加 D011 的 V2/ck32/ck64 对照。对清单中每一项运行 `film`。
2. `smooth_training_replay.py` 接收 `--dev-stage ck32 --dev-stage ck64 --dev-stage ck80 --final-dev-stage ck64`、训练目录和独立评分 JSON，输出 `videos/01-training-evidence.mp4`。随后用 `smooth_delivery.py assemble` 拼接、逐帧检查并制成本地播放器。
3. `gap_delivery.py` 使用同一份三臂独立评分和录像源输出 G04/G07/G08；再运行 `--comparable-only` 独立输出 G05。
4. `smooth_hub.py --smooth … --gates … --smooth-score … --gate-score … --out … --zip …` 复制校验过的媒体和证据到可单独解压的统一浏览目录，并生成覆盖全部播放资源的 SHA-256 清单。

本轮影片包含完整追车实录、识别、物理评审与独立评分。实车验证需另行开展。
