# Unity/A4 长训练复验

在一条已有赛道随机生成起点、朝向与障碍配置。每个布局从相同状态分别执行七种候选动作。所有样本经 Unity 电机、轮胎、接触、A4 摄像机闭环执行。场景管理器预加载物理环境进行渲染和判罚，驾驶策略接收局部观测；策略没有全局赛道站位或后续障碍布置输入。车身角速度和实速来自模拟器。本实验没有给实车发送 CAN 指令。

## 一条控制指令怎样产生

A4 的道路视觉被转换成车身前方 2、3.5、5.5、8 m 处的四个横向位置。视觉跟踪给出可见目标相对位置、横移和观测时长。接近一组目标时，上层用十八项局部观测作为输入，让训练得到的回归森林同时给七个动作预测收益，选最高的一项。动作包括沿用冻结 V2、保线、带有不同余量的小幅左右修正和不同速度。连续目标可以并入当前避让，车尾通过后逐渐回正。可选动作的定义、控制器以及判罚由代码实现。森林的分裂点和各动作的预期收益由闭环试次拟合。

底层根据四点道路斜率差算前方曲率，产生巡航速度。遇障时选中的动作可改变目标偏移和速度上限。控制器依照前瞻位置、目标偏移、实测车体角速度和前进速度给出目标偏航，随后差速电机模型转成左右轮指令。动作 0 会继续运行完整 V2。行级日志同时保存原始 A4 四点、目标跟踪、上下层选择、控制原因、期望车速和偏航、左右轮指令、实测运动、接触余量。

## 数据与复现

- [协议](PROTOCOL.md)与[训练布局](training_layouts.json)记录了 80 组种子和场景。真实闭环执行 560 次。四种转向代价按遇障路段距离归一化：车体实际航向相对道路切向的总变化、偏航命令总变化、横移和额外路程。正的车身至桶净距最多按 0.50 m 计收益。碰撞、出界、未过判定点均记失败。
- [训练动作排名](fixed_reference.json)以正常完成数优先。恒用 V2 完成 72/80，七个动作择优的训练集上限为 80/80。[恒用动作 0 的实跑回归](fixed_zero_check.json)保留同一轨迹、轮指令和原决策字段。补充的 20 个恒定动作对照引用同布局 V2 原始盲测，新增试次数为零。
- [开发验证](development.json)在相同场景比较基线和六份候选，共 19 × 7 次。ck64 在 19 项中完成 16 项，在两个混合整圈中完成一个。V2 总完成数相同，二者各自另有一个独有成功。所有候选均未通过严格开发门。优先级排序选中 ck64 作为实验候选，用于独立盲评。80 个布局都曾用于训练；最终选中的是用前 64 个布局、448 次闭环训练的较早检查点。
- [冻结声明](frozen.json)记录模型、源码、所有开发实测 SHA256 及冻结时刻。[模型](checkpoints/ck64/model.json)文件 SHA256 为 `25eae55ecbe436b816ed50cc22f3ffd26ab8fd6a4c1ae607f876e898056b9f84`。独立评分方随后公开新 24 个局部场景和 8 个完整圈场景。按预登记顺序实际执行原 V2 与 ck64，两臂拥有相同摄影、模型、初始位姿与物理步长。`runs/{b,l}NN_{base,learned}.json`保存实际终止状态和轨迹。
- [事件日志](events.jsonl)分别记录提交、真实完成与已落盘结果恢复。缓存命中不计入实跑。[回放核验](film_replays)分别检查摄影重跑与训练或开发原件。原始摄像序列保留在本地 `.work/frames/<id>`（20 Hz 追车与车头）及 `.work/camera/<id>/a4_samples`（5 Hz 真实 A4）。
- [训练轨迹上的独立车线诊断](lane_diagnosis.json)使用车体实速和偏航重投影前一帧，研究视觉跳变。盲评冻结的软件未加载这里分析的候选滤波器。

判罚使用与道路和桶几何相交的车身矩形。车身任何一个角超出路面就终止，因此此实验的道路判罚比实赛“四轮出界”更严格。曲率、道路进度和几何净距仅用来生成、评价场景；训练集的成绩表示对当前模拟赛道的采样结果。
