# 左转问题点与候选修复分析

2026-10-12。问题先于修复候选记录；历史原件见 `evidence/`。本报告没有宣称车辆功能已修复。

## 红灯是否必然左转

现有 MapAssist 包含有条件的红灯绕行：必须先学到 reference、成功融合和定位、接近入口，且 OA/branch 空闲，才禁用前方外环边并求内部图路径。它没有无条件“看见红灯就左转”命令。所选路线方向由图决定；本测试要求的是东北路口进入内部后再退出，不是沿外环东北弯行驶。

原四场短程冷启动没有完成首圈图学习，因此证明的是红灯停车和转绿恢复。新外圈真实首圈及红灯实跑已经覆盖到融合失败处，并保留了单独视频。

## 自动融合的输入语义不一致

精确快照有 1014 个真实 candidate 样本，4321 个数值逐项一致，重新调用原构造器后 RMSE 仍为 3.4044631404 m，超过原 3.0 m 门槛。五个 OSM 外节点是 graph junction；它们与 Unity 物理路口的对应不能仅由 OSM 推出。原自动方法用拓扑 chord 转角期待物理转角，但真正的四个圆弧位于路口之间，默认 2 m 特征窗口又远小于弯曲区。

A3 没有 drivable mask；失去车道像素不能被当作自由空间。仅改变门槛不能证明对应正确。真正自动修复需要有来源序列、时间与里程计配对、分支/端点和不确定性的真实路口观测，仍未实现。

## 内圈失线

同 worker 验证的内圈在完成首圈前因真实 lane 支持不足停止。邻近姿态下另一次 B 记录曾有临界投影片段；相近姿态不等于相同 mask 或处理状态。已分析时延，没有证据把本次失线归因于额外日志。保留原停止守卫，不把 unsupported 改成 supported。

## 先验接线方案与限制

候选使用独立、默认关闭的 Unity adapter；不编辑 semantic 核心源文件。配置明确给出官方逻辑 ID 到 control portal 的人工关联、场景坐标及定向边几何。它保留失败的自动融合结果，不伪造 similarity、不重缩放 reference、不改变 trust。

只支持正向 `02 → 06 → 03`：左入、右转、左出。06 是所选右转结束 portal，03 是左出弯结束 portal，都不是物理路口中心。复用 `official_node_positions_odom` 状态字段时，其值必须按显式标定的投影 portal 解读。

原段内 tracker 对密集几何会把 ABC 压在一个很短的段上，无法预瞄后续弯。候选仅在显式模式改用连续弧长预瞄，入口与每次投影限制仍为 2 m，局部连续投影、单调进度和异常拒绝保持。默认类不替换。

Unity consumer 原先先检查视觉 ABC，再消费 semantic 命令。候选只让有效的显式地图 detour、新 ABC、新命令且 age ≤0.25 s 拥有地图跟踪；正常车道失线、过期 RGB、E-STOP、所有权和命令守卫继续停车。`currentCorridor=true` 的视觉宽度上下文仍可能阻止此 detour，是保守停止的组合限制；首次测试明确用 `currentCorridor=false`，不放宽 TTL。

目前仅有严格的外圈真实快照可供 warm start。内圈没有快照，必须取得新的真实完整首圈。不得把外圈 reference 称作内圈学习。内圈 start x=68.76 与配置入口 x=67.463517 相差约 1.296 m，2 m 入口门槛余量有限；即使投影通过也不证明原 LYA 能平顺进入，实跑须记录入口距离、朝向、首 ABC 和请求。

该候选仅完成离线验证：topology 18 项、tracker 18 项、transport 16 项分别通过；默认 worker 三 tick 对照通过；实际外圈保存 reference 的重新计算和加载通过。最后一项仅给了一次明确供应的协议 tick，没有模型推理或车辆运动。C# 未编译，标定模式没有闭环结果；地图输入授权仍待用户选择。
