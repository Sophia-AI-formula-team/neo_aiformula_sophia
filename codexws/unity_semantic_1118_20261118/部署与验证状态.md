# 1118 Unity 接线部署（0.4.3）

供应商1118 ZIP原始导入为0.4.2；首圈红灯采样排除问题修复为0.4.3。源码标准位置：`workspace/src/aiformula/perception/semantic_planning_system`。修改前分析见同目录 `关键问题报告_首圈红灯污染参考线.md`。

## 实际接线

Unity相机→既有识别与LLP选点→本目录semantic_joint_worker.py加载原ROS包→MapAssist输出ABC→固定版本LYA→MapAssist速度门→原Unity差速驱动。运动状态由Rigidbody形成理想里程计；进程内消息适配，不是ROS2 DDS。当前没有动态OA/branch发布源，初始空闲和分支默认值仍在使用，不能声称完整避障联调。bbox模式关闭。

最终仿真参数覆盖：`detour_lookahead_m=2.5`、`detour_entry_radius_m=1.8`；`detour_max_cross_track_m=2.0`保持原值。MapAssist核心仅修正建图排除条件，详细差异见Git；配置选择及失败证据保留。实跑相关12项回归测试通过，其余原包测试问题未据此宣称解决。

## 启动与恢复

使用现有Unity MCP 6400的framed bridge；`run_1118.py --help`列出源目录、worker目录、Simulator、bridge脚本、输入哈希与有界超时等要求。输出放原包目录之外，已有输出目录拒绝覆盖；进入试跑前要求干净GUI Edit模式和正确场景。使用本目录 `AIFormulaJoint1118Trial.cs`，保留原harness，不替换原控制和物理代码。

本机用户明确授权必要时重启后，针对Simulator唯一进程进行了重启，另一UnityLab未操作。`AIFormulaJointMcpBootstrap.cs`及原meta需一并保留在目标Simulator的Editor目录，并核对Application.dataPath限制；不要像旧实验那样在Editor仍运行时删掉启动脚本，否则下一次域重载可能再次失去桥。此引导只启动目标项目的MCP，不改全局EditorPrefs。其他机器应审查其限定路径后适配。

runner在Play开始后设置本次渲染30FPS、vSync=0并写入`render_settings_receipt.json`，避免无上限Editor渲染导致感知调度异常。不得据此修改物理步长；实验结束恢复原渲染值并通过MCP检查。
