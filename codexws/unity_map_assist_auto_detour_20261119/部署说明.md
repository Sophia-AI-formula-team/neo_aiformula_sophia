# MapAssist Auto 0.4.5 红灯绕行仿真

本目录使用 PR #42 的 Semantic 0.4.5 源码，基线为 `1f099e2ddaf18ebde1cdfcac80f7d6f948719338`。验证场景为 Unity `MotorControllerValidation`，起点在右下角弯道。

## 内外圈配置

| 车道 | runner 参数 | 最小规划转弯半径 | 参数文件 | 实跑地图快照 |
| --- | --- | ---: | --- | --- |
| 内圈 | `--lane inner` | **6.0 m** | [tune_10.json](profiles/tune_10.json) | [accepted_map_snapshot.json](accepted_map_snapshot.json) |
| 外圈 | `--lane outer` | **5.5 m** | [outer_r55.json](profiles/outer_r55.json) | [accepted_map_snapshot_outer.json](accepted_map_snapshot_outer.json) |

两圈共用 6.0 米绕行前视和 0.7 米触发余量。LYA 在绕行阶段使用 `v_t=0.55 m/s`、`lambda_v=0.04` 和原值 `lambda_a=2.5`，恢复视觉循迹后用回原参数。Semantic 与 LYA 核心、车辆物理和跟踪保护沿用原版。

## 从右下角复现

1. 在已安装 LYA 和识别 worker 的专用 Simulator 会话中连接 Unity MCP。确认场景为 `MotorControllerValidation`，编辑器处于干净的 Edit 模式。备份两个补丁涉及的 C# 文件并记录 SHA-256。原始 `AIFormulaJoint1118Trial.cs` 为 `baa608195c491d369ac91439a14c0e0185d5f79e0a866a8a89b7e8e1f08b7f00`，原始 `AIFormulaSemanticPlanning.cs` 为 `cf506d82e22f1cf10ea26011229bad71c3e368a97121d9673039bb25ea0911a8`。
2. 将两份 C# 文件复制到空暂存目录，保持相对路径并统一为 LF。在暂存目录按顺序应用 `unity_warm_detour.patch` 和 `unity_observation_110s.patch`，每次先执行 `git apply --check`，再执行 `git apply`。将输出转回 CRLF，核对下方命令使用的哈希后放回原路径，通过 MCP 导入并确认编译完成、Console 无错误。第二个补丁将测试程序的红灯后观察时间从 70 秒延长至 110 秒。
3. 为此次试跑创建独立的 worker 目录，复制 `semantic_joint_worker.py`。按上表复制同一车道的参数和地图，在 worker 目录分别命名为 `trial_parameters.json` 和 `accepted_map_snapshot.json`。地图来自该车道首圈的实跑匹配，worker 会校验源码树、参考线长度和拓扑节点。
4. 在本归档目录运行以下 PowerShell 命令。`$lane` 取 `inner` 或 `outer`，`$case` 使用未用过的试验名。`$bridgeScript` 指向 Simulator 上一级项目的 `workspace/tools/invoke_unity_bridge.py`。为其余路径变量赋值，并按实际 MCP 监听端口调整 `--port`。

```powershell
$runnerArgs = @(
    $case
    '--lane', $lane
    '--output-root', $runs
    '--source-root', $semanticPackageRoot
    '--worker-root', $workerDir
    '--simulator', $simulatorRoot
    '--bridge-script', $bridgeScript
    '--port', '6400'
    '--expected-harness-sha256', 'd87e823b354af3ccd8af63d2a1d2c4bba2c32bcdd6210ac7d3a2ffc132d5f5eb'
    '--expected-transport-sha256', '34e03fbef168c1515ca61da4710c44d4993f168dfffa785823960792b530347f'
    '--wall-timeout', '155'
)
python .\run_detour.py @runnerArgs
```

5. 在 `result.json` 和 `events.jsonl` 中确认红灯识别、实际左转、回到主路及恢复视觉循迹后至少继续行驶 5 米。退出码 2 表示验收失败或输入文件在运行中发生变化。结束后恢复原始 C# 文件，核对 SHA-256，再通过 MCP 导入并确认返回干净的 Edit 模式。

### 源码字节校验

Windows Git 的换行转换可能使同一个 commit 的源码树哈希不同。复现时可将 0.4.5 包复制到试验目录，按已测基线将以下三份文件保存为 LF，其余文件保留原有字节。两个地图快照使用相同的源码树校验值 `6aa6bdc1d2c4171d829fb25010eb50931f559e0018e8a3f98e39ebbc40ca4bd5`。

- `semantic_local_planner_ros/tests/test_auto_turn.py`
- `semantic_local_planner_ros/tests/test_ubs_map_assist.py`
- `semantic_planner_core/setup.py`

## 验证结果

- **内圈 6.0 米通过。** `tune_10` 在仿真 98.77 秒回到主路，恢复视觉循迹后实走 5.06 米。绕行中有 138/1064 个移动采样达到角速度指令限幅。[内圈试跑数据](tuning_summary.json)
- **外圈 5.5 米通过。** 首圈实驶 281.28 米，红灯停车、转绿恢复并闭环匹配，RMSE 为 0.279 米。复用该外圈地图热启动后，仿真 103.14 秒回到主路，恢复视觉循迹后实走 5.04 米。外圈用 6.0 米时，UBS 找不到满足半径约束的曲线并停车。两次外圈绕行使用相同地图、起点和接线，参数仅相差最小规划转弯半径。[外圈试跑数据](outer_validation_summary.json)
- 相机识别与 Rigidbody 里程计是运行时输入。RGB 灯牌估距生成既有 8.5 米 `flag_stop`，场景灯状态用于试验编排和记录。OA/branch 沿用仿真默认状态。这里的结果来自 Unity 与进程内 ROS 接线，视频和原始日志保留在本地。

## 历史试跑

`detour_01` 至 `detour_07` 的参数与记录继续保存在 `profiles/` 和 [summary.json](summary.json)。复现时用内圈地图，仅应用 `unity_warm_detour.patch`，其 harness SHA-256 为 `f46ecd9ae868ca23f4451a2bff811b20d3942d08a98051c14f836c46456c99c7`，runner 参数 `--wall-timeout` 为 `125`。七次均实际左转入内。`detour_03` 的 LYA 与施加角速度指令达到 −2.00 rad/s，实测 −0.098 rad/s，随后触发横向偏差或航向超限。`detour_07` 的绕行参考进度为 41.06 米。
