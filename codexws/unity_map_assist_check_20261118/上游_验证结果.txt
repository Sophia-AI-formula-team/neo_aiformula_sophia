map_assist 检查修正版：验证结果

一、本次处理
1. 闭环时检查前后两帧 odom 之间是否在起点附近穿过闭环线，避免采样点跨过起点却刚好落在判定范围之外；方向、距离等其余限制仍保留。
2. 地图重置后清除已处理的红灯事件。绕行期间若距离标志先变 False、再变 True，同时确认新的红灯，则在当前绕行结束后处理该事件；同一持续为 True 的旧事件不会在出口反复触发。
3. 修正融合失败原因的诊断，并增加 fusion_ambiguity_warning 状态：候选存在全局位置或节点对应歧义时提示；仍按既定的角度限制和最低分规则选择，不以这个提示阻止融合。
4. 更新旧测试中已变化的接口、异步融合等待和测试输入，新增闭环、连续红灯以及官方拓扑与合成路线的检查。旧测试中“有歧义则必须拒绝”调整为检查“按此前约定选最低分并报告歧义”，并非消除了歧义。测试数和断言有变化，不能将失败数量的差值全部当作生产代码修复数。

二、自动检查
上一版随包完整测试：213 项，65 项失败、5 项错误。本版：222 项，2 项失败、0 项错误；其余 220 项通过。
重点功能检查：56 项通过；Unity 适配器 flag_stop 接口检查通过；全部 58 个 Python 文件通过 Python 3.8 语法编译检查。这些均不是实际 ROS2 DDS 或完整车辆动力学测试。

仍失败的两项是合成路线中官方节点与预设拐角的精确对应检查，期望偏差分别小于 0.35 米和 0.2 米，当前约 1.00 米。程序在这类数据上可能接受融合却选到不够准确的节点对应关系；没有实测路口真值时，不能根据低拟合误差断定实际路口正确，也不能保证任意起点都一定对应成功。这两项没有通过，也没有改成跳过或放宽误差。

三、1118 日志离线回放
内圈、外圈原始 odom 与视觉点分别回放到节点：均检测到闭环并接受融合，点到轨迹拟合 RMSE 分别约 0.179 米、0.338 米。外圈发现另一种竞争节点对应，位置差约 1.01 米；内圈本次未发现同类候选。这里的低误差不等于节点真实位置误差。
另外一次回放人为构造 flag_stop=True：两场均能进入 detour_tracking，所选节点为 02->06->03，并生成平滑路线。该标志并非真实距离检测器输出；回放没有让车辆实际走完全程，不能证明完整绕行、真实停车距离或动态避障表现。回放使用 40 米最短里程、2.5 米闭环半径、25 度闭环航向、3.2 米匹配误差上限、4 米暂定转弯半径，并假设 OA 空闲。

四、观察和限制
用 ros2 topic echo /map_assist/status 观察 map_fusion、fusion_ambiguity_warning、traffic_mode、traffic_reason、detour_node_ids 和 smooth_plan_reason。warning=True 表示程序发现其他有竞争力的节点对应方案，本版依照既定规则仍选最低分；warning=False 也不能证明真实节点位置正确，因为候选搜索不是穷尽搜索。
flag_stop 必须由外部节点持续发送；要区分两个红灯事件，距离标志需在两次事件之间回到 False。尚未在真实 ROS2 DDS、完整 Unity 或实车上验证。
首圈 OA 等不可信路段默认 max_detour_gap_m=2.0 米；缺口超过这一限制（加上采样容差）或不可信总长度过大，融合会拒绝并退回 odom_only。退回轨迹中这些路段仍被标记为不可信，不能用于地图方向辅助；这并不保证长距离避障后一定能融合。
