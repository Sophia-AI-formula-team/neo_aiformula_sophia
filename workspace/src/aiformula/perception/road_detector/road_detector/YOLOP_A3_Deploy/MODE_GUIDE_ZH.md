# A4：当前实际运行什么

## 版本关系

对外版本名为 **A4**，软件版本 **4.0.0**，Git 标签 **a4**。
这是对之前发布的 a3-v76 重新命名，没有重新训练、替换权重或改变推理行为。
源 checkpoint 的 V76 标识、哈希和实验记录保留，用于追溯。

## 单帧不是只识别一张

单帧模式会持续处理视频，只是每帧都独立识别，不参考上一帧。
之前 V14 的 ROS 节点也是这样运行的。现在运行新权重中的单帧部分，
不是退回 V14，不是只处理第一帧，也不是切换到 CPU。

| 入口 | 输入 | 当前行为 |
|---|---|---|
| `predict(image)` | 当前 RGB | 独立输出当前车道和物体 |
| 自带 ROS 节点 | 相机图像话题 | 调用 `predict(image)`，日志和 JSON 明确显示 `single_frame` |
| `predict_frame(...)` | 当前 RGB、序列 ID、采集时间、标定后的地面投影 | 对齐上一帧原始车道概率，再与当前预测融合 |

时序增强只作用于车道。物体头仍识别当前图像，没有加入物体跟踪。
所有模式仍然是一套共享骨干、一份权重、车道与物体两类独立输出。

## 为什么演示有增强，ROS 默认没有

Unity 演示提供了准确的相机位姿和地面投影，因此可以把上一帧的车道预测
对齐到当前画面。实车移动后，上一帧与当前帧的位置不同，不能直接叠加。

当前 ROS 节点只订阅图像，没有接入经过验证的相机标定、相机与车体的安装关系，
以及与图像采集时间同步的相机位姿。所以它没有调用时序接口。
**直接启动当前 ROS 节点，不能得到演示中的时序增强效果。**

## 已完成与尚未完成

- 已完成：模型、权重、时序模块、Python 接口、单帧 ROS 接口和部署文档的发布。
- 已验证：导出结果与训练端一致；时序输入、状态重置与两类输出的代码测试。
- 尚未完成：实车标定与同步位姿接入，以及接入后的时序效果和 AGX Orin 性能验证。

因此，“模型包已发布”不等于“实车时序增强已经启用”。A4 改名不会改变这个状态。
下一步是[时序接入与 Orin 验证任务 #34](https://github.com/Sophia-AI-formula-team/neo_aiformula_sophia/issues/34)，
不是继续训练或通过改名自动开启功能。输入矩阵和状态说明见 [TEMPORAL.md](TEMPORAL.md)。

## 为什么目录和接口还带 A3

`YOLOP_A3_Deploy`、`yolop-a3-runtime`、`yolop_a3_runtime`、`yolop_a3_perception`
及原 ROS 话题名称作为兼容接口保留，避免现有安装命令和调用方失效。
识别版本以文档、软件版本、权重清单和 Git 标签为准，当前均为 A4。
旧标签 `a3-v76`、`a3-v14`、`a3-v6` 不移动、不覆盖。
