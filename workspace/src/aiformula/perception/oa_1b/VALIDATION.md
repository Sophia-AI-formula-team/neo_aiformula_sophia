# OA 1B 0.1.1 验证记录

## 旧版和新版在同一套上、下游切换

使用隔离的 amd64 ROS 2 Foxy/GPU 容器，回放相机原图和静态里程计。运行原 AV314、原 LLP 和车道选点、原电机 console、原 LYA、原 MapAssist 和 OA 2.1。安装两次只构建 `oa_1b`，旧 `mapassist` 命令的 SHA-256 一致。

- 实际 DDS 看到只有原 AV314 发布公共识别结果。新版 MapAssist 订阅私有灯态和停车标志。四个同一源时间戳的样本中，原 JSON 都是 50 个红像素，OA 1B 去重后都是 25 个。
- 第三步运行新版时，开旧版会被同一把启动锁拒绝。对新版发 Ctrl+C，第三步节点退出，原 YOLOP、原 LYA 仍在用同一 ROS 域。随后同一套上、下游成功接回旧 `mapassist`，同时启动新版同样被拒绝。
- 再次启动 `mapassist_b inner 50` 后发 SIGHUP，第三步节点全部退出，原 YOLOP 和 LYA 仍在运行。之后分别结束各终端，DDS 节点为零。
- 台架的四个对齐样本中，原 LYA、MapAssist 最终指令、电机仲裁选中的速度一致，DDS CAN 帧也和电机记录逐字节一致。原 C++ LLP 在最后单独停止 Allnodes 侧时返回 245，相同旧 LLP 曾在隔离测试中单独复现 SIGINT 析构段错误，第三步停止与重启均成功。

## 同灯复核回放与耗时

将三场外圈原图及对应的原 YOLOP JSON 按源时间戳重放。420 个检测帧中 3 帧已过期。再次亮红的 50 帧由 41 帧判红提高到 47 帧。82 个熄灯帧未新增红判。原来有 20 帧达到 50 像素，去重后低于 50。

首轮测得旁路首次实际推理耗时约 685 ms，超过 500 ms 图像时效。已把一次预热放在第三步宣布就绪前，使用实际成对的原始图像。旧的 MapAssist 逻辑在第一帧新鲜实验结果发出后才进入运行。复测预热约 619 ms，之后条件触发 10 次，耗时中位数约 17 ms，最大约 101 ms。独立 PyTorch 模型峰值分配约 252 MiB，另有 CUDA 运行时开销。该数字来自桌面 GPU 回放。实车要同时观测原 YOLOP 的帧率和 Jetson 剩余显存。停车点距离和带轮运动仍待车端验证。[逐场回放数据](evidence/replay.json)
