# Mask 定位与持续降噪：验证边界（2026-09-27）

这一版已经把当前完整 mask 接入第二圈定位，不再只靠 VectorNav 跟踪路线。但是，**现有真实单圈 bag 没有通过连续定位验证，尚不能认为可以上车跑定轨迹**。

## 实现范围

- VectorNav 提供初值；当前 mask 投地后，与第一圈冻结的 consensus 匹配。
- 对粗线带使用 0.45 / 0.9 / 1.35 m 多尺度线方向估计，选择最小合格尺度，匹配局部线带中心；不放宽线性度、覆盖率、残差或创新量门限。
- 默认只修正横向和航向；纵向每帧约束回当前原始 VectorNav，避免直线或对称弯道中的不可观测漂移被错误积累。
- 先匹配旧图，通过源时间、接收时间、代次、VN 有效性与停车采集检查后，才提交该帧修正和降噪证据。当前帧不能先写图再匹配自己。
- 冻结路线和定位参考图不变。新地图至少 3 帧支持后加入有界历史降噪层；正常退出独立保存，不自动升格为驾驶参考。
- 两个版本定位不可信都 HOLD 零输出。重新获得可信定位也不自动开车。

当前重新采集沿用原匹配器的跟踪创新量门限（平移 0.12 m），不会自动恢复到首次定位的 0.45 m 门限。若失锁后偏移跳变超过跟踪门限，应保持停车，检查数据与原点，再重启节点、加载原 bundle 并重新采集；当前没有在线全局重定位服务。

## 有真值的合成实验

同一组合成相机、赛道、噪声和漂移：第一圈 1001 张 mask 建冻结地图，第二圈 160 张 mask，未改变输入来获取更好数字。

| 指标 | 原始 VectorNav / 未修正融合 | Mask 修正后 |
| --- | ---: | ---: |
| 位置 XY RMSE | 0.2332 m | 0.1654 m |
| 横向 RMSE | 0.1649 m | 0.0105 m |
| 航向 RMSE | 0.0300 rad | 0.0142 rad |
| 地图点到真值车道距离 P95 | 0.3587 m | 0.0534 m |
| 地图点在真值 20 cm 内比例 | 64.79% | 100% |
| 真值车道的 20 cm 覆盖率 | 71.62% | 100% |

160 / 160 帧通过算法检查；纵向误差基本不变。这是已知真值的离线实验，不是实车精度、闭环驾驶或 DDS 延迟证明。

## 真实数据：保留失败，不以低残差代替成功

`rosbag2_2026_01_20-15_31_07` 中读取原始完整 mask、CameraInfo、静态 TF 和原生 VectorNav。按实际消息到达顺序处理，仅使用已到达且不晚于 mask 的位姿；源数据不改时间戳。整包 1810 帧 mask，VN 源时效 250 ms、配对间隔 150 ms、后缀 mask 时效 500 ms。

| 冻结历史地图 | 后续待匹配 mask | 接受 | 结论 |
| --- | ---: | ---: | --- |
| 前 60 s（默认） | 916 | 0 | 没有通过连续定位 |
| 前 15 s（独立诊断） | 1586 | 2 | 只有开头两帧通过，未达到 runtime 的连续 3 帧采集条件，降噪层为空 |

后缀不是独立第二圈，没有定位真值。部分拒绝由历史地图覆盖/有效线支持不足导致；15 s 场景还出现创新量及最终内点检查拒绝。不能单凭这两次试验把所有问题归结于某一种原因，更不能调松安全门限把拒绝变成“成功”。

默认场景首帧含参考索引构建约 1.15 s，而 matcher 本体 P95 约 2.8 ms；后者不能掩盖初始化成本。节点在 HOLD 且已输出零命令时加载索引，加载完成后重新采集新鲜输入；这仍不构成硬实时停车保证。

## 如何复验

运行 README 的 `mask_localization_replay.py` 命令。每次会创建新的 `.artifacts/mask_localization_<UTC>_<ID>/`，包含源码哈希、全部参数、逐帧接受/拒绝、匹配耗时、数据时序与图像。拒绝帧不得显示成持续有效的修正定位；图中的接受点也不等于控制状态机已放行。

本地 Windows 单测与 Python 3.8 语法检查不能代替 ROS 2。组织仓库的 `Lane teach-repeat (ROS 2 Foxy)` CI 对对应提交进行 colcon build/test 和私有话题 DDS smoke；以该提交实际 CI 结果为准。CI 不连接车辆，不验证电机零指令、手操急停或真实闭环轨迹。

下一项实车前证据应是同一时钟/标定下的完整建图圈和独立重复圈，先离线测连续定位可用率、拒绝原因、跨圈偏差，再做断动力和封闭场地低速验收。
