# 1117 Unity 试跑：输入接线审计

## 直接结论

这次复用了旧的 Unity 仿真适配层，**不是原生 ROS 话题实跑**。避障与外部分支占用没有接入实时输入：worker 使用 `avoidance_initially_idle=True`，Unity 请求不发送 `avoidance_active` 或 `branch_active`，因此两场成功试跑中这两个状态一直为 false。这是无避障、无外部分支占用的测试假设，不是收到真实话题并证明始终空闲。

上次只报告匹配通过，没有说明这两个固定状态以及自动红灯后的绕行失败；这是交付说明遗漏。两场结果仍能证明**在这些前提下**新包接受了仿真数据并给出匹配结果，不能证明避障、外部分支切换、完整 ROS 通信或实车环境正确。

## 每项输入来自哪里

| 原包输入 | 本次 Unity 接线 | 常数／限制 |
| --- | --- | --- |
| odom | Unity Rigidbody 位置、朝向、线速度和角速度，经轴变换送入 worker 的 `_on_odom` | 随车辆变化；是理想仿真值，不是 `/aiformula_sensing/gyro_odometry_publisher/odom` 的 DDS 接收。未提供实际协方差，shim 填全零 |
| 视觉 ABC | A4 车道结果经现有 LLP 选点送 `_point_cb` | 随画面变化。内圈启用既有 `component-only` 适配策略，外圈 baseline；首场内圈有持续无有效选点并停车 |
| 红绿灯 | 当前图像经已标定 RGB panel 检测，真实检测输出经 `_on_light_state` | 随图像变化；A4 原始检测仍显示但不参与灯色投票。试验工具控制场景灯的时刻；场景真值没有直接进入语义输入 |
| LYA 速度命令 | MapAssist ABC 输出→固定版本 `withoutkalman_0312` / `lya_0221` 原类→`_on_controller_cmd` | 命令随选点变化，但使用现有 same-frame TF 抵消，`current_pose` 为本地零姿态；不是动态 ROS TF 验收 |
| `/lane_stop_flag` | 未连接 | 参数 `avoidance_initially_idle=True`；没有外部避障事件，保持 false |
| `/map_assist/branch_active` | 未连接 | 原类初始化为 false；没有外部事件，保持 false |
| `/map_assist/reset` | 未连接 | 每次启动独立新 worker；没有测试在线 reset |

worker 支持请求中显式给 `avoidance_active`、`branch_active` 并调用原回调，但本次 Unity 的 JSON 请求没有这些字段，不能将“支持字段”误写成“已经接入实时信号”。若后续要求避障全链路，必须先识别仿真中的真实事件源，接入并验证 false→true→false 及数据缺失；不能为了运行直接灌固定值。

## 版本标识错误

复用的 worker `ready()` 里 `semantic_revision` 字符串固定为 `1115_joint_map_0.4.0`。这是**错误/过时的诊断标签**，不是本次实际载入版本。实际路径指向本地1117工作树，运行时 MapAssist SHA256 `1ec558071c6b27b72158ca6d307f7d92f0e4fd5a97ba067fbe317cbc7b08b253`，源码树 SHA256 `08f539392f19059c166f348d448cdf30c36679fd67ac2f6c974cf9b0f8ec755d`，记录在每场 `worker/ready.json` 和运行日志。版本字段已在本地升到0.4.1。

为避免事后改变被测接线并冒充已重跑，这个 PR 保留原 worker 的测试身份；后续接线改为从实际包元数据和源码哈希生成标签，并针对错误标签增加回归验证，再重新跑。现有结果不能拿固定字符串证明版本。

## 原包原生 ROS 接线

原 `map_assist.py` 仍订阅 odom、ABC、避障 Bool、分支 Bool、reset Bool；启用交通与速度门控时另订阅灯色 String 和控制器 Twist。原生订阅的存在，不等于本次仿真 shim 已通过 DDS 接入这些话题。实际部署和缺失事件源要求见 [1117_部署说明.md](1117_部署说明.md)。
