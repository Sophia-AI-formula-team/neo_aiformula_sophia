map_assist_joint 验证结果（2026-11-15）

运行环境：Windows，本地 Python 3.8.10，NumPy 1.24.4。ROS 节点测试使用模拟消息和模拟 ROS 接口，不是真实 ROS2/DDS。

1. 新增测试
联合匹配与轨迹测试：8 项通过。覆盖非最近点的有序组合、任意记录起点和正反方向、对称歧义、官方节点配合模拟圆角轨迹、长避障段直线与不可信标记、未观测闭环缺口、参数校验。
节点集成测试：10 项通过。覆盖后台线程、待匹配和匹配失败时的 Odom 视觉辅助、未可信路段不纠偏、OA flag 优先、红灯等待、融合完成后的内部路径选择、重置后丢弃旧结果。
上次融合回归测试：3 项通过。
旧节点中选择的状态、输入、红灯投票、速度门控和 OA 所有权测试：16 项通过。
两个启动文件的模拟测试：9 项通过。

2. 完整核心测试
完整核心测试 103 项中 96 项通过、7 项失败，失败均位于继承的 test_route_fusion.py。5 项期望融合通过，但新算法判断存在多解；1 项因拒绝原因字符串与旧算法不同；1 项在节点位于人造尖角的测试中，定位误差约 0.464 米，超过旧测试 0.3 米要求。这些失败没有被忽略，也没有修改测试来掩盖；有些测试假设节点位于弯道，但定位精度与成功率仍须进一步验证。

3. 代表性模拟
使用官方 topo 节点和人为生成的圆角矩形 Odom：程序判断候选存在歧义并保留 odom_only。它不能代表真实赛道数据，但说明仅凭目前信息不能保证首圈拓扑融合一定通过。
使用另一组非对称人工拓扑和 Odom：模拟节点测试通过后台融合、图绑定、确认红灯后选择内部节点，以及 OA 介入时让出三点。该结果不验证实际场地的内部道路边界或转弯可行性。

4. 耗时范围
本机一次约 679 个 Odom 样本的非对称合成轨迹，后台融合约 2.1 秒；同时运行的简单 50 毫秒睡眠循环最大间隔约 0.065 秒。该测试不包含 ROS2 调度、车辆计算平台或真实相机负载，不能据此推断实车实时性。

5. 尚未验证
未运行真实 ROS2/Foxy 或 colcon 构建；未使用实际 rosbag；未上车测试。需要用实际采集数据核对闭环、避障区间、外圈节点和内部节点位置、计算耗时以及红灯绕行道路。候选搜索不是穷举，算法通过不保证拓扑对应或内部道路正确。
